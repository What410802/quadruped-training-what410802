### 4.1 规则/约束

- `docs/reference/team-race-2026.md` §2.2 和 `comp/CONTRACT.md`：
  - 允许：IMU、编码器；额外可用**模拟真实相机、雷达**；本队选深度相机、不采用雷达；相机需模拟真实噪声/延迟/外参；保留 blind fallback。

  - 当前 actor 45 维盲策略合规；critic 259 维特权（height_scan 187）只能 teacher/critic。
- 现有训练仓库**没有** camera/depth sensor 配置；`docs/environment.md` 说 mjlab 1.6 camera/depth 走 `mujoco_warp` GPU RenderContext（不经 EGL）；接相机前必须先测渲染开销。

### 4.2 建议实现（新对话从研究 API 开始）

1. **先确认 mjlab 1.6 相机/深度 API**：读 `.venv` 里 `mjlab` 的 sensor/camera 配置、`mujoco_warp` RenderContext 用法；查训练仓库 `env_cfgs.py` scene/sensor 结构。
2. **加一个独立 depth task**（不要破坏 `black-basic-obstacle` 盲任务）：
   - 例如 `black-basic-obstacle-depth` / `black-part2-depth`；
   - trunk/头部安装前向深度相机：64×64 或 96×96，FOV 60–87°，20–30 Hz，depth 0.1–3 m；
   - 场景渲染成本先测 1/10/100 iter，尝试 1024/2048/4096 envs。
3. **观测/网络**：
   - 方案 A（推荐先做）：深度 → body 系局部高度图（17×11 或 32×32）→ MLP/小型 CNN 特征（64–128D），actor = 45 proprio + 特征；critic = 259 特权 + 可选深度特征。
   - 方案 B：深度图直接 CNN encoder（64×64→64/128D）+ 45 proprio；更通用但更贵。
   - 保留 blind 45 维任务/权重作为 fallback；相机可 dropout，训练时随机关相机跑一部分 episode。
4. **相机 DR**：深度噪声、丢帧/延迟 0–2 帧、外参扰动、遮挡、不同 FOV；策略 50 Hz，相机 20–30 Hz，保持上一帧或使用短历史。
5. **部署契约**：导出 actor 输入维度会从 45 变 45+depth_feat；需要同步 rl_sar/depth 推理 wrapper；先不冻结为最终版本。
6. **100 iter cost smoke 验收**：无 NaN/CUDA 错误、actor obs shape 正确、每 iter 时间/显存记录、深度图/局部高度图可视化正确；然后才考虑 500/1000 iter 课程对照。
7. **优先级**：先让相机 sensor + 观测管线跑通并测成本；再决定 A/B 方案和是否加 teacher-student（height_scan teacher 已现成，可先做特权 teacher 作为过渡）。
