# 零点语义：上电、运行中、离线（以及程序要自维护什么状态）

> 这份文档回答三个问题：**① 板子在上电/运行/离线时各报什么；② 我们凭什么把"绝对位置"定下来； ③ 验收程序应该长什么样、验收当天按什么顺序演。**
>
> 依据：官方手册 §3（单圈绝对值编码器：**掉电丢圈数**，上电读数回到 0…2π）、S1 实测（同一上电周期内 读数连续累计，跨 148 个转子圈、约 148 次越过候选零点都没有跳变；09-29 的手转又补了一次：12 个区间、 步进 ≥2° 共 0 次）、S2e 实测（断链后板子**不卸力**）、S2a/S2b 实测（读数是**里程计**）。
>
> 缩写与符号见 [`glossary.md`](glossary.md)；报文的定点标度见 [`fixed-point.md`](fixed-point.md)； 现场步骤见 [`runbook.md`](runbook.md)。

## 1 三种情形：板子报什么、我们缺什么

| 情形 | 板子报的 `pos` | 我们能确定的 | 缺的那部分 |
|---|---|---|---|
| **上电**（含掉电重上电） | 从 **0** 开始累计，即**整数部分恒为 0**、范围 `[0, 32768)` tick；它表示"从**此处及后方最近的一个候选零点**量起的角度" | 在**一个零点区间内**的位置（精度 1 tick = 0.001735° 输出端） | **是这个区间里的哪一个**：物理位置差 `k × 56.842°`（输出端），`k` 未知 ⇒ 必须用外部参考消歧 |
| **运行中**（同一上电周期） | 里程计：连续累计，可正可负，跨候选零点**不跳** | 绝对位置（相对上电那一点），只要我们不丢帧 | 无（S1 实测；`pos` 已到 1.4 M tick ≈ 44 转子圈仍连续） |
| **离线** | 分两种：板子**没断电**（只是我们收不到回复）⇒ 恢复后读数继续；板子**断过电** ⇒ 退化成"上电" | 见 §4 | 见 §4 |

**结论**：真正需要"处理"的只有**上电那一刻**（以及等价于它的"板子断过电"）；运行中的跳变是异常兜底。

## 2 更正一处旧说法：运行中跳变不是常态

之前 [`real.md`](real.md) §5.4 把"运行中板子临时换基准"和"上电认错"写得一样重。按 §1， **跳变只可能发生在上电那一刻**（板子换基准的时机）；运行中同一上电周期内它维护里程计， 正常越过候选零点不会跳。所以：

* 程序里的 `Δpos == k×32768` 检测 **保留**，但定位改为**兜底**：防固件差异、防板子在异常时（欠压/复位）换基准；
* dry run 的注入开关（`--fake-jump-frame` / `--fake-sawtooth` / `--fake-datum-turns`）继续有用：
  前两者模拟"未知/异常行为"，后者模拟"上电落在别的候选零点"——**后者才是主线**。

## 3 程序要自维护的状态（内存，不落盘）

**为什么可以不落盘**：板子在掉电后什么都不记得，而验收/实验期间**我们的程序运行时段时间 ⊇ 电机在线时段** （程序先起、电机后断；或者断了我们也能立刻发现）。所以"位置账本"放在进程内存里就够， 掉电重启时重新按 §4 锚定即可。（真要跨进程保留，就把 `turn_base` 与 `offset` 打印出来抄进记录表。）

| 状态 | 含义 | 何时更新 |
|---|---|---|
| `turn_base` | 本会话的**圈基准**：`pos_ticks = raw + turn_base`，其中 `turn_base = k × 32768` | 上电首帧按 §4 求一次；离线重锚时更新 |
| `offset` | **软件零点**相对 `pos_ticks` 的偏移（tick）：`q_ticks = pos_ticks + offset`，`0` 命令就是去 `q_ticks = 0` | `reset` / `offset` / `o±` 命令；被判定为上电或跳变时按 §4 修正 |
| `online` | 是否在收回复（连续 N 帧无回复 ⇒ 离线；再收到 ⇒ 恢复） | 每帧 |
| `last_pos` | 最近一次有效 `pos_ticks` | 每帧（仅在线时） |
| 事件 | "上电锚定（k=?）"、"离线重锚（k 变化 ?）"、"跳变修正" | 发生时打印并记入收尾汇总 |

## 4 怎么把 `k` 定下来（三个判据）

设 `raw ∈ [0, 32768)` 是当前报的 tick，`ref` 是"我们相信的物理位置"（tick）：

```
k = round((ref − raw) / 32768)      // 最近的整圈；半圈以内都能选对
pos_ticks = raw + k × 32768          // 本会话的绝对位置
```

| 场景 | `ref` 从哪来 | 备注 |
|---|---|---|
| **验收开始（首次上电）** | 不需要参考：**直接接受当前位置** —— `reset here` 把"这里"定为软件零点（或先 `raw` 转到编码器真值零点再定） | 用户明确接受"上电前手动转到随机位置不影响程序输出"：因为后面一切都是相对的 |
| **需要复现某个已知姿势** | 上一次记下的读数（记录表里的 `pos` tick 或 `q` 度）：`--expect-deg` / `expect` 命令 | 差 ≈ 整数个区间就自动修；这正是"上电确认零点未跳变"（任务书第 3 条的提醒） |
| **离线恢复** | `last_pos`（"位置没动"假设） | 验收期保证输出端不动或移动 < ±1/(2N) 输出圈（= ±半区间）⇒ 必选对 |

**离线怎么判**：连续 N 帧没回复（`motor_ctl` 现在是 40 帧 ≈ 0.2 s）⇒ 置 `online=false`； 恢复后**第一帧**做一次重锚判定：

* `|raw + k×32768 − last_pos| ≤ 半区间(=16384 tick)` ⇒ 认为板子没断电，只是我们丢了帧，静默继续；
* 差值恰好在整圈附近（`last_pos − raw` 接近 `k×32768`）⇒ 板子断过电，按上式重锚并**打印事件**；
* 两者都不像 ⇒ 停下报警（手动确认位置后再 `reset`）。

**离线期间 / 恢复的那一两帧只发零力矩，不要位置目标。** 板子刚上电或刚回来时，它自己的读数空间 与我们的账本可能差整数个区间，而板子解位置目标时按"最短弧"折到自家读数附近 ⇒ 任何位置目标都可能 让它按差一整圈的目标去追，给出几十 N·m 量级的冲击（离线自检里复现过：`--fake-off-after` + `--fake-hand-deg` 组合，修之前力矩峰值 52.5 N·m，修完 0.3 N·m）。所以顺序固定为：

1. 判离线 ⇒ `hold_torque=false`（零力矩），因为这时"目标"已经没有意义；
2. 恢复后拿**这一帧**的 `raw` 做重锚（只改 `turn_base`），算出恢复后的真值位置；
3. 之后才恢复出力。默认**维持原目标**（用户可能正希望电机继续去那个角度），只在 `--recover-hold` 下才"就地重新起目标"。

第 2 步之后的位置真值 = 掉线前的值 + 离线期间被推的角度（手推就会有这一项，程序会把三个数都 打印出来对照）。

## 5 验收程序的简易 CLI（设计；重构时落地）

命令尽量少，且每条对应任务书的一句话。括号里是"验收时哪一步用它"。

| 命令 | 语义 | 用在哪 |
|---|---|---|
| `state`（`p`） | 打印：`pos` tick / `turn_base` / `offset` / 在线状态 / 最近事件 / 目标与差 | 每一步演示前展示 |
| `reset` | 把"此刻"定义为软件零点。**无参时问一句**"回到编码器真值零点吗？[y/N]"：`y` ⇒ 先走 `raw`（到编码器真值零点），到位后把软件零点设在那里；`N` ⇒ 就地设零点。也可以直接写 `reset here` / `reset raw` 跳过提问 | 验收开始（首次上电后），以及任何想换零点时 |
| `raw` | 转到**编码器真值零点**：上电首帧 `pos = 0` 的那个候选零点（本会话内可重复） | 配合 `reset raw`；也可单独用来指认"哪个点是编码器零点" |
| `0` | 转到**软件零点**（`q_ticks = 0`） | 任务书② "慢慢回归 0 位置" |
| `<角度>` | 转到"**相对软件零点**的指定角度"（度） | 任务书② "键盘输入一个角度" |
| `+<角度>` / `-<角度>` | 相对**当前位置**的增量 | 找记号笔位置 |
| `offset <度>` | 直接设置软件零点偏移量（绝对值版） | 任务书③ "零点正向偏移 30°" |
| `o+30` / `o-30` | 在现有偏移上加减（保留，等价于 `offset <旧值 ± 30>`） | 同上，手快 |
| `mark` / `goto-mark` | 记下/回到"记号笔那个点" | 任务书③ 的验收基准 |
| `expect` / `fix` | 与记录值对照（差 ≈ 整数个区间就是上电落了别的候选零点）/ 按建议修正 | 上电检查（任务书③ 的提醒） |
| `hold` / `stop` | 位置保持 / 零力矩（卸力） | 任务书④ 手转前后 |
| `q` | 先卸力再退出 | 收尾 |

**逻辑要点**（实现时照做）：

1. 位置一律用 `int64` 的**转子侧 tick**（见 [`fixed-point.md`](fixed-point.md) §5），`q_des` 与 `offset` 都是 tick；
2. 上电首帧：`turn_base` 按 §4 定（默认 `k=0`，即"接受当前位置"），随后 `reset` 只改 `offset`；
3. `offset` 改变时**同一帧**把 `q_des` 一起挪同样的量，保证物理目标不动（否则驱动板会按 56.8° 的误差使劲， dry run 里实测力矩冲到 41.8 N·m）；
4. 离线恢复的重锚**只改 `turn_base`**（不改 `offset`），这样软件零点对应的物理位置不变；
5. 每次锚定/重锚/修正都打印一行 `事件`，并在收尾汇总里给出计数——验收时要能一眼看出"这次动过几次账本"。

## 6 验收当天：步骤与时序（约 15–20 分钟）

| # | 时间 | 做什么 | 说什么 / 期望 |
|---|---|---|---|
| 0 | 2 min | 接线、权限、`serial_probe --port` 探针 | 复用 S0 的结论：`baud_base` 整除、构造成功 |
| 1 | 2 min | 上电，跑 `motor_ctl`，`state` | "板子掉电丢圈数，读数从 0 起；我们的程序按'接受当前位置'锚定，`turn_base=0`" |
| 2 | 2 min | `reset`（选 `N` 或 `y`）→ `state` | 说明"软件零点 = 这里"；选 `y` 时会先走到编码器真值零点 |
| 3 | 3 min | 任务书②：`0` → `<角度>`（如 30°）→ 记号笔标记 | 输出端确实到位；读数是相对软件零点的角度 |
| 4 | 3 min | 任务书③：`mark` → `offset 30` → `state` → `<角度>` | 记号笔那点读数变 **+30.00°**；再命令同一个角度时电机**回到记号笔那点**（少转 30°） |
| 5 | 4 min | 任务书④：`stop` → 手动把输出端**慢慢**转过编码器零点（前后各一次）→ 手动把输出端**转到另一个候选零点附近**模拟"上电落到别的圈" → 断电 → 上电 → 程序自动/按提示重锚 → `hold` → 回到记号笔那点 | 手转时不跑偏；断电重上电后程序报"重锚 k=±1"并仍然回到记号笔那点 |
| 6 | 2 min | `q` 退出、填记录表、拍照 | 记录表在 [`runbook.md`](runbook.md) §5 |

> 第 5 步就是任务书要求的"零点跳变"验收，但把重点放在**上电那一刻**（真正的风险点）， 而不是"运行中会不会跳"（§2：不是常态）。
