# essential_core：只留核心（两个状态 + 一条 MIT 公式 + 一个站姿）

> 这是 [`../essential/`](../essential/README.md) **再砍一刀**的版本，与 [`../src/`](../src/)（完整版）并列。
> 目标是**一次读完就能说出"这次任务的仿真部分到底做了什么"**：上电阻尼 → 按 S 起身 → 按 D 塌回去。
> 全部代码 3 个文件、约 490 行（含注释）。

## 与 essential/ 的差别

| 去掉了 | 为什么可以去掉 |
|---|---|
| **全部量测与遥测**（四足触地/高度/竖直度/漂移、起点/收工摘要、按 R 的前后对比） | demo 是人看着窗口的，程序不必给结论；要数字回归就用完整版 `--mode sim` 的判定与退出码 |
| **命令行**（`cli.h` + `args.h`，~200 行） | 参数全是 `state.h` 里的 `constexpr`；场景路径自己"往上找带 `scenes/` 的那一层" |
| **站姿文件与指纹校验**（`stance_file.h` + `stance.h`，~240 行） | 站姿就是 12 个关节角 + 一个基座高度，直接内联成常量（数据来自 `../models/stance.txt`，逐位相同） |
| **自适应斜坡**（按姿态选 0.1 s / 1.5 s） | 固定 1.0 s 就够（实测见下），核心版不需要为不同起始姿态定制表现 |
| **电机统计与撞限幅计数** | 那是"说明限幅有没有起作用"的遥测，不是控制必需 |
| **多起点**（`--start stance/rest/side`）与 `start.h` | 核心版只有一种起点：模型原姿态（`mj_resetData`，即 `raw`） |
| 电机非理想项与转子侧换算 | essential 里本来就没有（死区/延迟/噪声/齿比只存在于完整版） |

**留下的**：两状态机、MIT 公式（`τ = kp(q_des − q) + kd(q̇_des − q̇)`）、**双重限幅**（我们控制这一层先夹一次，模型自己的 `ctrlrange` 再夹一次）、官方 Simulate 窗口、终端按键、`R` 回起点。

## 怎么跑

```bash
cd ..   # 仓库根目录（有 pixi.toml）
pixi run cmake -S @20260927_motor/cpp/essential_core -B @20260927_motor/cpp/essential_core/build -G Ninja -DCMAKE_PREFIX_PATH="$CONDA_PREFIX"
pixi run cmake --build @20260927_motor/cpp/essential_core/build

pixi run @20260927_motor/cpp/essential_core/build/essential_core
```

在**运行它的那个终端**里按键（不用回车、不回显）：

| 键 | 作用 |
|---|---|
| `S` | 站立模式：`q_des` 从按下那一刻的关节角在 1.0 s 内平滑推到站姿 |
| `D` | 阻尼模式：只剩 `τ = −kd·q̇`，狗在重力下自己塌回去（上电默认就是这个） |
| `R` | 回到起点（模型原姿态）并切回阻尼模式 |
| `Q` / `Ctrl-C` | 收工：关掉窗口、恢复正常终端、退出码 0 |

窗口里：**空格 = 暂停/继续**、鼠标操作相机、面板能改 `qpos`/`ctrl` 看实时数值；直接关掉窗口同样正常收工。

## 站姿与参数（都在 `src/state.h`）

- **站姿** `kStanceQ[12]` / `kStanceZ`：完整版 `stance::Search` 搜出来的结果，与 [`../models/stance.txt`](../models/stance.txt) 的 `q` / `z` 两行**逐位相同**；换了模型要重新生成再同步过来（命令写在注释里）。
  为什么不能直接用模型默认位形（所有关节 = 0）：膝关节会越界、质心还落在四足中心后面 0.18 m，实测见 [`@20260923_mujoco/docs/stand.md`](../../../@20260923_mujoco/docs/stand.md)。
- **增益** `kKp = 80`、`kKd = 3`（讲义 §1.4 的实机输出侧那一组）、`kKdDamp = 0.5`（阻尼模式）。
- **斜坡** `kRamp = 1.0 s`：实测（`--start raw`，9 s 仿真）0.5 / 0.8 / 1.0 / 1.2 / 1.5 s 在"上电直接按 S"与"先塌下 3 s 再按 S"两种情形下**都能站住**；只有 0.3 s 从趴卧起会被自己掀翻。取中间的 1.0 s 两条路径都稳。

## 验证

- **编译**：`-Wall -Wextra` 零警告；语言服务器无诊断。
- **行为**（核心版自己不打数字，所以用一个不入库的抽检程序：`#include` 本目录的 `state.h` 跑无窗口仿真，末态按完整版判定行同一口径打印）：

  | 脚本（`--start raw`，固定斜坡 1.0 s） | essential_core 末态 | 完整版 `--mode sim --ramp 1.0` 判定 |
  |---|---|---|
  | `0.05:stand`（9 s） | z 0.4864 m、竖直度 0.24°、末段 max\|q̇\| 0.000 | z 0.4864、竖直度 0.24°、max\|q̇\| 0.000 ✓ |
  | `0.05:stand,5:damp,5.5:reset,6:stand`（11 s） | z 0.4864、0.31°、0.002 | z 0.4864、0.31°、0.002 ✓ |
  | `3:stand`（先塌下再按 S，9 s） | z 0.4864、0.24°、0.000 | z 0.4864、0.24°、0.000 ✓ |

  三个场景逐位吻合 ⇒ 核心版的控制程序与完整版/最简版是**同一套行为**（不同的是有没有输出数字）。
- **真终端按键**：`S` → `按键 → 站立模式`、`D` → `按键 → 阻尼模式`、`R` → `按键 → 回到起点（模型原姿态）、切回 阻尼模式`、`Q` → 退出码 0（终端正常恢复）。
- **`R` 之后再按 `S` 仍然有效**：复位**保留仿真时间轴**（`mj_resetData` 会把 `d->time` 清零，而斜坡进度按时间算，不清零就会先卡住一段）——这个坑完整版与最简版都踩过。

## 文件

| 文件 | 管什么 |
|---|---|
| `src/state.h` | 站姿常量 + `motor`（5 个量的 MIT 指令、双重限幅、τ 公式）+ `ctrl`（两状态机、固定的 1.0 s 斜坡） |
| `src/main.cpp` | 官方窗口（主线程 `RenderLoop()`）+ 控制线程（装场景 → `Load` → 一步一循环）+ 终端按键 |
| `src/tty.h` | 终端按键（raw 模式 + 非阻塞轮询 + 析构复原），与 [`../essential/src/tty.h`](../essential/src/tty.h) 逐字相同 |
| `CMakeLists.txt` | 单独工程与 target `essential_core`；链 `mujoco` + `libmujoco_simulate` + glfw + `Threads::Threads` |
