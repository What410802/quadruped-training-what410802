两条**预告**（验收时会看到，都不是异常）：

- `move 0` 把输出端带到**转子零点**（板子本次上电的 datum），所以记号笔会画在**格边界**上；`mark` 会打印"离零点边界 +0 圈 +0.059°"这样的值（实机），这是预期（design.md §5.4 反例 3）。由此有一条纪律：**断电重上电后先 `check` / `fix`，再发移动命令**（§3）。
- 停稳后总有 ±0.05° 量级的固定偏差（静摩擦死区，上界 ≈ τ_f / K_P）：实机 `move 0` 停在 raw +26 计数（+0.045°）、`move 30` 停在 +30.041°。来源与 8 次实测见 [control-loop.md](control-loop.md)。

## 3 现场规则：手动转动允许范围与启动姿态（D14 / D20）

| 灯 | 场景 | 规则 |
|---|---|---|
| 🟢 绿 | 带电 `free` 手转 | 任意角度、任意多次、跨任意多个转子零点（`raw` 是里程计，无歧义） |
| 🟢 绿 | ④b：断电重上电、摆回参考附近（$\lvert\delta\rvert \le 20°$） | 程序**自动对齐**（D20）：打印 $k$、$r$、`offset` 变化；**电机不动**；`kAlignFix` 事件 +1 |
| 🟢 绿 | 程序重启（电机没断电）且输出端停在参考姿态附近 | $k = 0$ ⇒ 无动作，直接可用（"重启前摆回参考附近"是前提） |
| 🟡 黄 | 断电净位移 $20° < \lvert\delta\rvert < H$；或停在恰好 $\pm H$ | 余量小 / 二义点：换姿态重来（自动路径此时不执行、会停在 gate） |
| 🔴 红 | 断电净位移 $\lvert\delta\rvert \ge H$ | $k$ 的解释会翻转（design.md §5.4 反例 2）；硬 `fix` 会把账本修错 |
| 🔴 红 | 断电净转 ≥ 1 整输出圈 | 分支漂移（design.md §5.4 表 B）：读数差 $n \bmod 3$ 个 $S = 18.9474°$，此时 $k = 0$、`fix` 也修不了 ⇒ 只能靠本规则避免 |
| 🔴 红 | 断电重上电后**护栏未过**（`k` 超界 / $\lvert r\rvert > W$ / 首帧 `raw ≥ 32768`）仍硬发 `move` | 等于跳过检查：基准差一格时落点静默偏 $L = 56.8421°$ |

三条纪律：

1. 手转只在该卸力时卸力：**带电手转必须先 `free`**；带位置环时手只能把它推开几度（`kp` 会顶回来）。
2. **每次启动程序前（含程序重启）把输出端摆回参考姿态附近**（$\le 20°$、不净转整圈）；`--no-auto-fix` 时启动后先看检查行，再决定 `fix` 还是直接 `move`。
3. 断电期间的净位移与净圈数都要小（$\le 20°$、绝不整圈）；验收要"转一整圈"就在**带电**状态下用 `jog 1r` 完成（里程计连续、不受此限）。

程序侧对应输出（都只打印）：`check` / 启动检查在 $T_w = 9.4737° < \lvert r\rvert < H$ 时打印一行提示（R17）；自动对齐或 gate 时打印完整分解（$k$、$r$、`raw0` 证据与两种解释）。

## 4 构建、日志与运行

```bash
cd <仓库路径>                                    # 含 pixi.toml 与 @20260927_motor/ 的那一级（例：MyMonoRepo.d）
pixi run cmake -S @20260927_motor/cpp_part2_remake -B @20260927_motor/cpp_part2_remake/build
pixi run cmake --build @20260927_motor/cpp_part2_remake/build

T=<仓库路径>/@20260927_motor/cpp_part2_remake/build/tests/motor_core_tests
B=<仓库路径>/@20260927_motor/cpp_part2_remake/build/apps/motor_ctl/motor_ctl
RL=@20260927_motor/scripts/run_log.sh               # 日志包装（相对仓库根）
$T                                               # 先过核心自检（不接电机）
$B --no-send                                     # 看配置，不开串口：应看到 N = 19:3、L = 56.8421°
```

每条实机命令都用日志包装（行缓冲 + 自动命名到 `output/terminal/`）；`<阶段>` 用批次号 `b0` / `b1` / … / `b6b` / `b7`，方便事后对表。后面的命令里统一用上面设的 `$T` / `$B` / `$RL`（分终端做的话，每开一个终端先把这三行设一次）：

```bash
sudo $RL b4 $B --port /dev/ttyUSB0 --id 0
```

两种模式：

- **交互**（stdin 是终端）：最后一行是固定输入行（`>` 提示符），状态打印不会把它冲散；退格 / `Ctrl-U` 编辑、`Ctrl-D` 或 `quit` 退出、`Ctrl-C` 正常卸力退出（退出码 130）。②③ 的画线与标定必须用交互模式（人要在对的位置画线）。
- **脚本**（重定向 / here-string，无人值守）：`sudo $B --port /dev/ttyUSB0 <<< "move 0; wait 3; quit"`；`;` 与换行等效，`wait <秒>` 是语句。

角度：输入默认 `deg`，可加 `deg` / `rad` / `r`（`rev` 同义）/ `tick`（`32768tick` = 一个转子圈 = $L$）；显示一律是"±圈数 ± <360°"。帧行密度用 `--every <N>` 调（默认 20 帧 ≈ 0.12 s）。

## 5 逐批执行卡

### 5.1 批次 0–1：准备、转起来、量断链

批次 0 = §2 清单 + §4 构建与自检 + `$B --no-send` 干跑。

批次 1（转起来；带插值限幅与保护，这一步同时验证 P1）：

```bash
sudo $RL b1 $B --port /dev/ttyUSB0 --id 0
> move 5; wait 3; move -5; wait 3; move 30; wait 5; state
> quit
```

期望：每条命令先打印"目标 … 要转 … 按 vmax 直线约 X s"，随后帧行平滑逼近、出现 `⇒ 到位`；`state` 里 `turn_base +0`、`offset +0`（初值）、事件 1 条；汇总 `超时 0`、`merror 0`、温度正常。

量"断链不卸力"（S2e 复现，1 分钟，为后面所有"保持"行为定性）：

1. `move 30` 到位保持中，直接拔 USB 线（或另开终端 `kill`）——程序会报失联并退出，但**驱动板继续顶住**（执行最后一条指令）；
2. 观察 10 s：电机不松劲；
3. 断电，再上电：松。

记录：是否继续顶住 / 断电后是否松（结论与旧版 2026-09-29 实测一致：不卸力）。

### 5.2 批次 2：官方 SDK 例程（任务书 ①）

记录：编译是否一次通过、电机确实转、转速观感、断电时刻。

### 5.3 批次 3：手转看形态 + 上电基准重复性

目的是确认两件事，它们决定批次 6b 怎么写预期：(a) 读数形态是**里程计**（跨格不跳）；(b) 板子上电选 datum 是否稳定。

```bash
sudo $RL b3 $B --port /dev/ttyUSB0 --id 0
> state            # 记首帧 raw（例：+2832）
> free             # 零力矩，可手转
（手转：慢速让线所在格"正向跨一次、反向跨一次"，可再多跨几格；≤ 0.25 圈/s）
> state            # raw 应为连续累计值（可以 > 32768，表示已跨过 1 个转子圈）
> quit
```

判据：

- **跨格不跳**：帧行里 `raw` 连续增长/减少，跨过 32768（板子 datum 折点）时没有跳变、也不产生账本事件；`q` 与 `raw` 一一对应（默认 `offset = 0` 时相等）。
- 参考实测（[motor-real-202610011135-m1-ctl.txt](../../output/terminal/motor-real-202610011135-m1-ctl.txt)，帧 8860 → 8880）：`free` 手转时 `raw` +32256 → +41247、`q` +55.954° → +71.550°，连续无跳变；同一会话继续转到 `raw` +115854（`q` +200.967°，≈ 3.5 个输出端圈）。

上电基准重复性（旧版 S2f）：

- 把输出端停在**同一个物理位置**（贴桌沿/夹具的一个记号），断电 → 上电 → 立刻 `state`，抄首帧 `raw`；重复 3–5 次。
- 判据：3–5 次 `raw` 若都在 ±0.1° 量级内 ⇒ datum 稳定，批次 6b 的 `--pose-ref` 可以跨会话复用；若看到相差 ≈ 整数个 $L$ ⇒ datum 会跳格，批次 6b 每次都靠自动对齐/`check` 兜底（自动对齐默认开，D20）。

### 5.6 批次 6b：④ 断电重上电 + 自动对齐（✅ 已实现）

**6b-1 负侧（跨过线，基准会差一格 ⇒ 自动对齐会补格）**：

```bash
> quit                     # 卸力退出
（断电：拔电池 / 关开关）
（手把输出端移到线的**负侧 ≈10°**：|δ| ≤ 20°，绝不整圈）
（上电）
sudo $RL b6b $B --port /dev/ttyUSB0 --id 0 --offset-deg -30 --pose-ref <§6 表 A 的 raw>tick
> state                   # 核对：线处读数应已恢复 -30.000°；事件 2 条
> move 30                 # 落点应为"线前方 60°"（与批次 5 第 9 步同一点）
> quit
```

期望（数值按 $\delta = -10°$ 为例，见 design.md §5.4 的"算例"与表 A；D20 自动路径）：

- 启动检查：`d = raw0 - ref = 27003` ⇒ `k = +1`、`r = −5765 计数（−10.0004°）`；打印两种解释与 `raw0 < 32768` 的证据；提示一行（$\lvert r\rvert > 9.4737°$）。
- **自动对齐**（护栏三条件全过）：`offset −17294 → −50062`、`kAlignFix` 事件 +1、**电机不动**。
- `state`：线处读数恢复 **−30.000°**；事件 2 条。
- `move 30`：落点回到"线前方 60°"，读数 +30.000°。

**6b-2 正侧（没跨过线，基准没变 ⇒ 无动作）**：

同 6b-1，但把输出端移到线的**正侧 ≈10°**。期望：`k = 0`、`r = +10.0°`（提示一行）；**无自动修正动作**、无新事件；`move 30` 直接正确。

**可选反例 A（讲"为什么护栏不通过时必须停"）**：重复 6b-1 但加 `--no-auto-fix`：程序只打印检查、**停在 gate（零力矩）**；此时直接 `move 30` 会偏一整格 $L = 56.8421°$（读数正常、实物错格）——正是 design.md §5.4 反例 1 的现场版；正确做法是先 `fix` 再 `move`。

**可选反例 B（讲"程序重启 ≠ 断电"）**：把输出端停在离参考**一格附近**的位置，`quit` 后**不断电**直接重启（带同一组参数）：护栏会拦住（首帧 `raw` 大 / $\lvert k\rvert \ge 1$）⇒ 停在 gate 并打印两种解释；由人判断"没断电 ⇒ 不该 `fix`"（直接 `move` / `hold` 作为确认继续）。

**M4 之前的临时做法（可选，风险自负）**：没有 `check` / `fix` 时，重启后先用 `state` 读出线处 `q`，与 −30.000° 的差若 ≈ $k \times 56.8421°$，可以手动等价操作 `zero move <k × 56.8421>deg`（对 $k = +1$ 即 `zero move 56.8421`）。⚠️ 它不打印前提、不检查 $\lvert\delta\rvert < H$、不记 $k$——只在你确知"断电期间净位移 < 20° 且没转整圈"时用；正式验收请等 M4 的自动对齐 / `fix`。

**已实测（2026-10-02，实验台离线复现，`sim` 模型 + 真实 SDK + PTY）**：控制程序退出后实验台继续当设备进程跑（断电期间不积分、不回帧），脚本按"上电 → `move 0` 到线 → `mark` → 断电 → 移到线负侧 −10° → 上电 → 重启控制程序"走完，输出与上面的期望逐条对上：

## 8 虚拟实验台演练（无实机时先把批次 4–6a 走一遍）

两个终端：终端 2 跑实验台（假电机），终端 1 跑 `motor_ctl`（走**真实 SDK**，不需要 sudo、不需要电池）。

```bash
BD=<仓库路径>/@20260927_motor/cpp_part2_remake/build
$BD/apps/motor_sim/motor_sim           # 终端 2；启动会打印一行可直接复制的 motor_ctl 命令
```

把终端 2 打印的那行粘到终端 1（形如 `LD_PRELOAD=<…>/libpty_serial_shim.so <…>/motor_ctl --port /dev/pts/N`）。**`/dev/pts/N` 每次都不一样，必须用终端 2 打印的那个**（填错会连到别的终端，现象是控制程序收不到回复、被填的终端刷乱码）。

实验台 REPL 现有命令：`status` / `torque <N·m>` / `hold [<角度>]` / `release` / `power off|on` / `offturns <n>` / `datum <j>` / `line draw|angle|clear` / `wait <秒>` / `help` / `quit`；启动参数 `--print-interval <秒>`（0 = 关闭周期打印）、`--frame-period <秒>`。

| 步 | 终端 2（实验台） | 终端 1（motor_ctl） | 期望 |
|---|---|---|---|
| 1 | 启动，记下 `/dev/pts/N` | 粘贴命令启动 | 控制程序打印锚定；实验台开始有帧计数 |
| 2 | — | `move 0` → 记 `state` → 画线（终端 2 `line draw`）→ `mark` | 线夹角 ≈ 0°；标记点读数 ≈ 0 |
| 3 | — | `move 30` | 平滑到位；终端 2 `line angle` ≈ 30° |
| 4 | `line angle` | `zero move 30` → `state` | 电机**不动**（线夹角不变），终端 1 的标记点读数变 **−30.000°** |
| 5 | `line angle` | `move 30` | 落到线前方 ≈ 60°；要回线上用 `move -30` |
| 6 | `hold 60`（模拟手扳到 60°） | `free` → 看 `state` | 读数随外力变化；`hold` 收回 |
| 7 | — | `quit` | 先卸力再退出；实验台会看到超时（正常） |

批次 6b 也可以**完全离线**演练（design.md §3.7 的两层模型：真值层 + 上报层折圈）：`power off` → `offturns -0.0278`（或 `hold -10` 挪到位）→ `power on` → 重启控制程序看启动检查/自动对齐。§5.6 的"已实测"段就是这样跑出来的。
